# Node/PWA migration matrix

**Updated:** 2026-10-17. This matrix reflects source inspection of the supplied ZIP, not a live Git checkout. No production service or database was contacted.

| Domain/workflow | Existing authoritative implementation | PWA/Node replacement | Auth/tenant/data notes | Status and next verification | Rollback approach |
|---|---|---|---|---|---|
| Browser shell | Existing Next.js app and content | `pwa/` static HTML/CSS/vanilla JS served by Express | No business data should be served from service-worker cache | Present; run browser install/offline/accessibility tests | Route users back to existing web app; leave its files intact |
| Browser API access | ASP.NET Core API | Node same-origin proxy at `/backend/api/**` | Forwards cookies and CSRF header; restricts path and headers; provider webhook paths blocked | Present; Supertest suite not run in this environment because dependencies are not installed | Keep existing API authoritative; disable PWA deployment |
| Authentication/session | ASP.NET auth controllers, cookie session, CSRF, 2FA states | PWA sign-in UI via proxy | No localStorage token storage; actual upstream session rules remain authoritative | UI present; end-to-end session, logout, expiry and CSRF checks pending | Revert UI routing; no auth data migration |
| Customers | ASP.NET controllers/services + PostgreSQL/EF Core | PWA customer CRUD plus customer portal link management and public order/invoice portal via proxy | Must use session-derived business and upstream authorization | Source present; no staging API test in this run | Use existing Next.js workflow |
| Measurements | ASP.NET measurement services | PWA measurement creation/revision/history UI | Preserve revision history and customer/business relationships | UI source present; workflow not verified end-to-end | Existing API and Next.js remain authoritative |
| Fittings | ASP.NET fitting API and PostgreSQL | PWA fitting list/create/status UI through the restricted proxy | Server permission checks and DateTimeOffset conversion remain authoritative | Present in source; staging date/time and status checks pending | Keep ASP.NET endpoint authoritative; revert PWA route only |
| Orders/production | ASP.NET API and PostgreSQL | PWA orders and task/schedule screens via proxy | Server-calculated pricing, lifecycle permissions, optimistic versions and idempotency remain upstream responsibilities | UI source present; new changes need dependency-backed CI and staging workflow tests | Existing API remains authoritative; roll back PWA only |
| Staff/scheduling | ASP.NET staff, availability, leave and schedule services | PWA staff and scheduling screens via proxy; task assignment, blocked-task, next-step and daily overdue notices are queued through the existing outbox | Worker permissions and shop-level access must be verified on API | Source present; new notification code is uncompiled; schedule conflict/revalidation and delivery require CI/staging tests | Existing UI/API retained |
| Finance/payments | ASP.NET finance, invoices and subscription controllers | Partial PWA invoice list, free-form/order-linked creation, draft editing/deletion, issue/void, payment record/verify/reject, credit notes, receipt details, expense list/create/summary/export/void and expense-category create/update via proxy; no Node domain implementation | Payment verification/webhooks must remain server-side; proxy blocks webhook routes | Partial; provider flows and UI integration need staging tests | Existing API remains authoritative |
| Inventory | ASP.NET source includes inventory controller and migration | Partial PWA list/create/receive/adjust/history, CSV preview/hash-bound commit, and task-linked reserve/release/consume UI via proxy; no Node domain implementation | Do not deduct stock without tested transaction workflow | Partial; browser/API checks remain | Existing API retained |
| Storefront | Existing ASP.NET storefront API + Next.js public renderer/editor | Editor includes draft/theme, custom pages, SEO/navigation, drag/drop sections, media picker, template preview, DNS-verified domains, preview/publish/rollback; no PWA/Node replacement | Public published content must remain isolated from private tenant data | Source present; web build, browser E2E, publish/rollback and DNS smoke tests pending | Keep Next.js renderer and storefront routes |
| Node PostgreSQL access | EF Core in existing API | No Node repository/data layer currently wired | Node readiness probes the upstream ASP.NET `/health`; it does not connect to PostgreSQL directly. Do not point it at production expecting Node data access | Not implemented; requires schema review and explicit migration plan | No DB changes made by Node |
| Offline writes | No verified complete PWA sync layer | Service worker caches static shell only | API responses are excluded from cache; no IndexedDB mutation queue | Not implemented beyond shell fallback | Clear app shell cache; server records remain authoritative |
| External integrations/jobs | Existing .NET integrations; Redis queue primitives exist in source | No equivalent migrated Node handlers | Credentials and provider delivery require real-world checks | Partial/blocked by credentials and services | Keep current provider integrations in .NET |

## Cutover rule

No production traffic switch, schema alteration, or destructive change is authorized by this matrix. Migrate one domain at a time only after API contract comparison, tenant-negative tests, staging verification, data compatibility checks, and a rehearsed rollback.
